# ADR-0004 · 剪辑工坊：1.0 先交付「剪辑工程」，OpenReel 嵌入延后

- 状态：**已采纳**（2026-11-05，rc.1）
- 相关：[ADR-0001](./ADR-0001-tech-stack.md) 第 4 条与复审条件（「OpenReel 集成失败 → 退化为 FFmpeg 导出 + 外部剪辑」）

## 背景

最初的需求包含「开源剪辑工坊」。ADR-0001 计划在 beta.6 验证嵌入 OpenReel（MIT，浏览器时间轴编辑器）。到 rc.1 为止：

- 画布已经能产出成片：导出成片节点按画布顺序拼接、对齐配音、封装字幕（beta.6）。
- 创作者真正缺的是**在时间线上精修**：调整剪辑点、换配乐、调色、加转场。
- OpenReel 仍处于 alpha 阶段；把它嵌入为子应用需要稳定的「导入外部素材 / 时间轴」接口，以及额外的打包体积与安全审查（第三方 Web 应用运行在我们的窗口内）。本轮**没有**对 OpenReel 做实际集成测试。

## 决策

1. **1.0 交付「剪辑工程」**：导出成片节点可选「同时生成剪辑工程」，产出一个压缩包：
   - `project.mlt`：MLT XML 工程（MLT 是开源多媒体框架，Shotcut 的工程格式就是 MLT XML），时间线与成片一致——V1 为镜头，A1… 为配音（重叠时分轨），原声去掉时 V1 静音；
   - `clips/`、`voice/`：全部片段与配音（相对路径引用）；`subtitles.srt`；`README.txt`（打开方式）。
   - 目标软件：**Shotcut**（GPL-3.0，免费开源，Windows / Linux / macOS）。我们只生成数据文件，不分发、不链接 Shotcut 或 MLT。
2. **验证方式**：自动测试用 MLT 自带的命令行渲染器 `melt` 实际渲染该工程，逐帧检查画面顺序、用响度检查配音位置，与成片一致才算通过（CI 安装 melt）。
3. **OpenReel 嵌入延后到 1.1**，前提是：它提供稳定的工程导入格式或 API；能离线打包进桌面版；通过安全审查（只在独立的 webview / 独立进程中运行，不访问我们的 API Key）。届时同一份「时间线描述」（`Timeline`，见 `apps/server/src/exporter.ts`）可以再输出成 OpenReel 需要的格式。

## 后果

- 正面：创作者今天就能在成熟的开源剪辑软件里精修；格式公开、可被 melt 自动验证；我们不承担内嵌编辑器的体积与安全面。
- 负面：需要用户另装 Shotcut；字幕需在 Shotcut 的「字幕」面板手动导入 SRT（Shotcut 24.02+）；在 Shotcut 图形界面中的打开效果尚未在真机上确认。
- 可扩展：`Timeline` 已与成片导出共用，后续可增加 FCPXML（DaVinci Resolve / Final Cut）或 OpenTimelineIO 输出。
